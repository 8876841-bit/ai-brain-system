# Agent 核心概念

来自 45 天学习计划 Day 10-22 的手写问题。

---

## JSON 是什么？

一种数据格式，用于在程序之间传递结构化信息。

```json
{
  "name": "政立路",
  "area": 53,
  "type": "独居"
}
```

类比：就像一份有固定格式的表单，任何程序都能读懂。API 调用时，发送的请求和收到的响应都是 JSON 格式。

---

## Agent / 模型 / 程序，什么关系？

- **模型**：LLM 本身，负责理解和生成文字（大脑）
- **程序**：运行模型的代码，处理输入输出，调用工具（骨架）
- **Agent**：模型 + 程序 + 记忆 + 工具 + 规划的整体系统（完整的工作单元）

模型是 Agent 的核心，程序是 Agent 的骨架。没有程序，模型只能聊天；有了程序+工具+记忆，才能成为 Agent 去执行任务。

---

## 代码是我写的吗？（关于 Tool Runtime）

在 Agent 里，工具调用的分工是：

- **工具的描述（schema）**：你写，告诉 AI 这个工具叫什么、做什么、需要什么参数
- **模型决定调用哪个工具**：AI 自己判断
- **工具的执行代码**：开发者提前写好（Python 函数），或者用现成的 API

初学阶段：工具代码可以用现成的，你只需要写好描述和连接逻辑。随着能力提升，你会开始自己写工具函数。

---

## 什么是边界？

边界 = 告诉 Agent 什么能做、什么不能做、什么时候停下来。

在 System Prompt 里定义边界：
- 这个 Agent 只处理木作相关问题（能做）
- 不回答与装修无关的问题（不能做）
- 不确定时问用户而不是自己猜（停下来）

边界清晰的 Agent 不会越权，不会在该停下来的时候继续瞎跑。

---

## 第一阶段复盘：7 个核心模块的关系

| 模块 | 作用 |
|------|------|
| messages | 对话历史容器，存储所有轮次的对话 |
| system prompt | 角色和规则定义，Agent 的"工作说明书" |
| tool use | Agent 的行动能力，让它能做事不只是聊天 |
| RAG | 外部知识接入，让 Agent 能查自己的知识库 |
| ReAct | 推理+行动的循环，让 Agent 能处理多步任务 |
| memory | 跨对话的信息保留，让 Agent 记住你 |
| eval | 评估 Agent 表现，知道它哪里做得好哪里不行 |

这 7 个模块合在一起 = 一个完整的 Agent 系统。

---

## ReAct Loop 是什么？

ReAct = **Re**asoning + **Act**ing

循环步骤：
```
Thought（我要做什么）
→ Action（调用工具）
→ Observation（工具返回了什么）
→ Thought（根据结果继续思考）
→ ...直到任务完成
```

ReAct 让 Agent 能处理需要多步推理和多次工具调用的复杂任务，而不是一次性给出答案。

---

## Few-Shot 为什么有用？

Few-shot = 在 prompt 里给几个例子，模型从例子里推断出你想要的格式和风格。

为什么比说规则更有效：模型是从大量文本中学习的，给例子比给规则更符合它的"学习语言"。你说"请用简洁的风格回答"，不如直接给一个简洁风格的例子。
